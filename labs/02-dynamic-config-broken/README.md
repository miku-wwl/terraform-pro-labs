# Lab 02：用 `for_each` 构建稳定的动态配置

## 场景

平台团队维护着一份本地存储记录目录。旧配置使用列表和 `count`，资源地址依赖元素位置；一旦调整列表顺序，资源就可能被错误地替换。

你的目标是用业务名称作为资源身份，让目录项增删或调整顺序时，已有资源仍能保持稳定。同时，只有真正配置了相关选项的记录，才创建对应的设置资源。

## 需要掌握

- 用对象 `map` 表达结构化目录。
- 用 `for_each` 和业务键创建稳定的资源实例。
- 用 map 推导式筛选需要创建的子集。
- 用 `merge` 合并共享标签和记录专属标签。
- 将资源和输出组织成以记录名称为键的 map。

## 需要完成的改造

把 `catalog` 从列表改成以记录名称为键的对象 map，并将主要记录、版本控制设置和保留策略设置都改为稳定的 `for_each` 实例。

版本控制只应为明确启用它的记录创建；保留策略只应为提供了保留天数的记录创建。为 `catalog` 变量添加 `validation`：未提供保留天数时允许通过；提供时必须大于或等于 1。

记录标签需要和共享标签合并；同名时，以记录标签为准。输出也要使用相同的记录名称作为 key，分别汇总记录、版本控制和保留天数。

## 约束

- 只能编辑 `starter/main.tf`。
- 不使用基于位置的 `count`。
- 禁止添加 provider、凭据、外部数据或云资源。
- 禁用的可选配置不能生成对应的 `terraform_data` 实例。
- 空目录必须得到空 map，而不是报错。

## 完成标准

默认目录应得到 `archive`、`assets`、`logs` 三个稳定实例；版本控制和保留策略只为 `archive`、`logs` 创建。

替换目录输入后，资源实例必须继续使用调用方提供的业务键、值和标签优先级。无效的保留天数必须被 Terraform 拒绝。

相关文件：

- 可编辑：`starter/main.tf`
- 参考测试：`tests/public.tftest.hcl`
- 验证：`scripts/verify_tests.py`
